# ビジネス要求仕様書（BRD）

**文書種別:** ビジネス要求仕様書（設計・実装の前段階）  
**対象:** アルゴリズムトレーディング基盤（モデル学習・バックテスト・ExchSim 連携取引）  
**ステータス:** 草案（レビュー用）

---

## 1. 目的と背景

### 1.1 目的

利用者が、**計画したタイミングで機械学習モデルを学習**し、**過去データに基づく評価（バックテスト）**を経て、**シミュレーション取引所（ExchSim）上でリアルタイムに近い形で自動または半自動取引**を行えるようにする。  
これにより、戦略の妥当性を段階的に検証し、本番相当の環境に近づけてから運用判断できるようにする。

### 1.2 背景

- モデル品質は学習データの期間・再現性・評価方法に強く依存する。
- バックテストのみでは約定遅延・板の変化などリアルタイム要因が反映されない場合がある。
- ExchSim は本番とは異なるが、**実注文フローに近い検証**が可能な段階として位置づけられる。

### 1.3 本書の位置づけ

- **ビジネス要求**（何を達成し、誰が何をできるか）を定義する。
- システムアーキテクチャ、API 詳細、DB スキーマ等の**技術設計は本書の対象外**（別紙）。

---

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| 利用者 | 本システムを操作するトレーダー、クオンツ、または運用担当者。 |
| モデル | 価格方向・強度等を出力する機械学習モデル（学習成果物）。 |
| 学習（トレーニング） | 指定期間・条件のデータを用いてモデルを更新または新規作成する処理。 |
| 期日 | カレンダー上の**学習実行日**、または学習に用いるデータの**截至日（as-of）**等、運用で合意した日付概念。本書では両方を要求として区別する。 |
| バックテスト | 過去の市場データ（および可能なら当時のルール）を用いて、戦略・モデルの損益・リスク指標をシミュレーションする処理。 |
| ExchSim | 外部のシミュレーション取引所（API 経由で注文・約定・ポジションを扱う想定）。 |
| リアルタイム取引 | ExchSim に対し、市場データの更新に追随してシグナル生成・注文判断・発注を行う運用モード。**※「リアルタイムでモデルを再学習する」こと（オンライン学習）とは区別する。** 後者を要望とする場合は別要求として記載する。 |

## 3. ステークホルダー

| ステークホルダー | 関心事 |
|------------------|--------|
| 利用者 | 学習の計画・実行、結果の確認、バックテスト、ExchSim での検証取引。 |
| 運用・リスク管理 | 損失上限、キルスイッチ、監査ログ、再現性。 |
| 開発・保守 | 要求の明確化、テスト可能性、環境分離（学習／検証／シミュレーション）。 |
| ExchSim 提供者（外部） | API 仕様・可用性・利用規約（本書では前提として扱う）。 |

## 4. ビジネス目標と成功指標（例）

| ID | ビジネス目標 | 測定可能な成功指標（例） |
|----|--------------|---------------------------|
| G1 | 学習を「いつ・何を対象にしたか」追跡できる | 学習ジョブごとに期日・データ範囲・成果物 ID が記録される |
| G2 | バックテストで戦略を比較できる | 同一データ期間で複数モデル／設定の指標を並べて比較できる |
| G3 | バックテスト後に ExchSim で挙動を確認できる | 承認されたモデルでシミュレーション取引を開始・停止できる |
| G4 | 誤操作・過剰リスクを抑える | 本番相当モードは明示的承認と上限設定がないと実行できない（ポリシーは別途合意） |

※ 数値目標（例: シャープ比○以上）は組織方針で別紙とする。

## 5. スコープ

### 5.1 対象（In Scope）

- **計画に基づくモデル学習**（特定の期日に実行、または「その期日時点までのデータで学習」等の運用定義に沿った学習）。
- **バックテスト**（過去データに基づく評価）。
- **ExchSim 向けのリアルタイム取引モード**（シグナル生成、注文、ポジション・損益の把握を含む概念）。
- 上記を通じた**トレーサビリティ**（どのモデルでどの評価・どの取引か）。

### 5.2 対象外（Out of Scope）（初期リリースの例）

- 実取引所への直接接続、および実資金の入出金操作。
- 規制申請・適合審査そのもの。
- **オンライン学習**（マーケットが開いている間に連続的に重みを更新する方式）を必須とする要件（必要なら別 BRD で定義）。
- 利用者向けの請求・課金システム。

### 5.3 前提・依存（ビジネスレベル）

- ExchSim API が利用可能であり、アカウント・認証情報が発行されること。
- 学習用・バックテスト用の履歴データが、利用規約の範囲で利用可能であること。
- 「特定期日」の解釈（スケジュール実行 vs データ截至日）がプロジェクトで合意されること。

## 6. ユースケース概要

### UC-1: 期日を指定したモデル学習

**主アクター:** 利用者  
**要約:** 利用者は、合意した「期日」の意味に従いモデル学習を実行する。成果物（モデル）と、学習に用いたデータ範囲・パラメータが後から参照できる。

**ビジネス要求（高レベル）:**

- BR-UC1-01: 利用者は、学習ジョブに対して**実行予定日時**または**データの截至基準**のいずれか（または両方）を指定できること。
- BR-UC1-02: 学習完了後、**いつ・どのデータ範囲で**学習したかが記録されること。
- BR-UC1-03: 学習が失敗した場合、利用者が**失敗理由を確認**できること（ビジネス上必要な粒度）。

### UC-2: バックテスト

**主アクター:** 利用者  
**要約:** 利用者は、指定したモデル（および取引ルール）で過去期間のパフォーマンスを評価する。

**ビジネス要求（高レベル）:**

- BR-UC2-01: 利用者は、**評価対象のモデル**と**バックテスト期間**を指定できること。
- BR-UC2-02: バックテスト結果として、少なくとも**損益・取引回数・主要リスク指標**をビジネスで合意した単位で確認できること（具体指標は付録で列挙可）。
- BR-UC2-03: バックテストの条件（手数料・スリッページ等）を**明示的に定義**し、結果と一体で保存できること。

### UC-3: ExchSim でのリアルタイム取引

**主アクター:** 利用者  
**要約:** バックテストで一定の基準を満たしたモデルを用い、ExchSim 上でリアルタイムに近い運用を行う。

**ビジネス要求（高レベル）:**

- BR-UC3-01: 利用者は、**どのモデル（バージョン）で** ExchSim に接続するか選択できること。
- BR-UC3-02: リアルタイム取引中、**現在のポジション・未約定・損益の把握**に必要な情報にアクセスできること（定義は運用と合意）。
- BR-UC3-03: 利用者は**取引を停止**できること（緊急時を含む）。
- BR-UC3-04: バックテスト結果と ExchSim 運用は**別フェーズ**として扱い、移行時に**確認ステップ**を設けること（組織ポリシーに応じて必須化）。

| ID | 要求概要 | 優先度（例） |

## 8. 非機能要求（ビジネス観点）

| ID | 分類 | 要求 |
|----|------|------|
| NFR-01 | セキュリティ | 認証情報・個人識別可能情報をソースコードや共有ドキュメントに埋め込まない運用とする。 |
| NFR-02 | 可用性 | ExchSim 障害時は利用者が状況を把握し、取引を止められること。 |
| NFR-03 | 再現性 | 同一モデルバージョン・同一バックテスト条件で、検証環境上で結果を再現できること（許容誤差は別途定義）。 |
| NFR-04 | 保守性 | 学習・バックテスト・シミュレーションの責務が運用上区別できること。 |

## 9. ビジネスルール・ポリシー（合意事項として記載）

以下は組織ごとに調整する。**未合意のままでは実装判断できない項目**として扱う。

1. **期日の定義:** 「毎週金曜に学習」などのスケジュールか、「常に直近 N 日のデータで学習」か、両方か。
2. **バックテストから ExchSim への移行条件:** 例: シャープ比・最大ドローダウン・最小取引回数の閾値、および誰が承認するか。
3. **ExchSim での最大許容損失・ポジション上限**（シミュレーションでも運用ルールとして定めるか）。
4. **リアルタイム取引中のモデル差し替え**を許可するか（メンテナンス窓の要否）。

## 10. 受入条件（例）

学習・バックテスト・ExchSim を**それぞれ独立して**受入可能とする。

| フェーズ | 受入条件（例） |
|----------|----------------|
| 学習 | 指定期日／データ条件で学習ジョブが完了し、成果物 ID とメタデータが参照できる。 |
| バックテスト | 指定モデル・指定期間で結果が保存され、保存された条件を読み取れる。 |
| ExchSim | 選択モデルで接続・注文・停止が行え、主要な口座状態が確認できる。 |

---

## 11. 付録: 要求の曖昧さの解消（プロジェクト内で確認すべき質問）

1. 「特定の期日」は **(A) ジョブ実行日** と **(B) 学習データの截至日** のどちらを主に指すか、または両方か。  
2. 「リアルタイムトレーニング」が **リアルタイム取引** の誤記でないか。オンライン学習が必要なら、そのビジネス価値とリスク許容度は何か。  
3. バックテストで必須とする KPI の一覧（組織のレポート要件）。  
4. 利用者は単一組織内か、マルチテナントか（データ分離要求）。
